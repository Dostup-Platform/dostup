# План: модератор + чат поддержки

## 1. Аккаунт модератора

- Логин один и фиксированный: `moderator`. Пароль хранится как хеш в секрете `MODERATOR_PASSWORD_HASH` (bcrypt). Только модератор знает пароль; в коде/БД его нет.
- Edge function `verify-moderator-password` принимает `{ login, password }`, сверяет с секретом, возвращает токен сессии (как у создателей). Токен пишется в `localStorage` (`moderator_token`).
- Новая страница `/moderator` с собственным логин-экраном (стиль как `CreatorLoginForm`). Вход с главной — отдельная кнопка «Войти как модератор» рядом с существующими ролями (или скрытая ссылка `/moderator/login`, на выбор; в плане — видимая кнопка).
- Edge function `validate-moderator-session` для проверки токена при загрузке `/moderator`.

## 2. Что видит модератор

Дашборд `/moderator` с разделами:

**a) Создатели** — таблица всех `creator_accounts`:
- Имя, тип аккаунта, дата регистрации.
- Число учеников (уникальные `simple_users`, у которых есть `simple_purchases` со статусом `completed` на продуктах этого создателя).
- Суммарный доход (сумма `amount` всех `completed` покупок продуктов создателя).
- Число продуктов, число активных уроков.
- Статус: «Активен» / «Заблокирован».
- Действия: **Сбросить пароль** (модальное окно — модератор задаёт новый пароль, edge function `moderator-reset-creator-password` обновляет хеш), **Заблокировать / Разблокировать**, **Удалить навсегда** (с подтверждением — каскадно удаляет продукты, расписания, материалы, покупки, учеников, привязанных только к нему).
- Пароли создателей **не показываются** (только хеши в БД). Управление только через сброс.

**b) Общая статистика** — сводка сверху: всего создателей, всего учеников, общий доход платформы, число продуктов.

**c) Поддержка** — список всех чатов (см. п.3).

## 3. Блокировка создателя

- Новое поле `creator_accounts.is_blocked boolean default false`.
- Edge function `verify-creator-password` возвращает ошибку, если `is_blocked = true` («Ваш аккаунт заблокирован»).
- Все данные сохраняются, разблокировка через модератора.

## 4. Чат тех. поддержки

Логика: у каждого пользователя (создатель / учитель / ученик) **один** чат с модератором. У модератора — список всех чатов.

**База:**
- `support_threads` — один тред на пользователя:
  - `user_type` ('creator' | 'teacher' | 'student'), `user_ref` (имя или id), `display_name`, `last_message_at`, `unread_for_moderator int`, `unread_for_user int`.
- `support_messages`:
  - `thread_id`, `sender` ('user' | 'moderator'), `text`, `created_at`, `read_at`.
- Включён Realtime для обеих таблиц.

**UI у пользователя (создатель/учитель/ученик):**
- В правом верхнем углу шапки, **слева от иконки уведомлений**, добавляется иконка `MessageCircle` с бейджем непрочитанных. По нажатию открывается экран чата «Тех. поддержка» (один чат, без списка). Только текст.
- Аналогично в `TeacherDashboard` и в дашборде ученика.

**UI у модератора:**
- Раздел «Поддержка» — список всех тредов (сортировка по `last_message_at`), бейдж непрочитанных у каждого. Открытие — переписка справа. Может писать любому.

**Уведомления:**
- Создаём триггер на `support_messages` → push:
  - При сообщении от пользователя → push всем устройствам модератора (новый `push_tokens.role = 'moderator'`, токен модератора регистрируется на `/moderator`).
  - При сообщении от модератора → push устройствам этого пользователя (по существующей механике `push_tokens`).
- Бейдж непрочитанных обновляется через Realtime подписку.

- `CreatorDashboard`, `TeacherDashboard`, `Dashboard` (ученик): в шапке справа добавить иконку «Сообщения» слева от «Уведомлений». При активной вкладке `support` — белый цвет, как у других активных пунктов.
- Логика `handleTabChange("support")` рендерит компонент `SupportChat` в основной области.

## 6. Технические детали

- Все операции модератора (сброс пароля, блок, удаление, чтение статистики, отправка сообщений от имени модератора) выполняются через edge functions с проверкой `moderator_token` через `validate-moderator-session`. Service role используется внутри функций.
- RLS на `support_threads` / `support_messages`: чтение/запись только через edge functions (политики `using (false)`), потому что у пользователей нет настоящего `auth.uid()` (кастомная авторизация). Клиент дергает edge functions: `support-list-threads`, `support-get-messages`, `support-send-message`. Realtime работает на публикации; для безопасности тексты не содержат приватных данных кроме самого сообщения — это допустимо для MVP.
- Секрет: попрошу добавить `MODERATOR_PASSWORD_HASH` (bcrypt-хеш желаемого пароля) перед запуском.

## 7. Миграция БД (одной миграцией)

- `alter table creator_accounts add column is_blocked boolean not null default false;`
- `create table support_threads (...)` + GRANT + RLS (deny-all для anon/authenticated, edge functions через service_role).
- `create table support_messages (...)` + GRANT + RLS аналогично.
- `alter publication supabase_realtime add table support_threads, support_messages;`
- `alter table push_tokens` — расширить допустимые роли (если есть check) для `'moderator'`.
