## Цель

На главной странице — единый вход для учеников и создателей. Кнопка **«Зарегистрироваться»** открывает выбор режима: **«Автор курса»** или **«Онлайн-школа»**, далее — ввод имени-логина и собственного пароля. Существующие создатели продолжают входить общим паролем. LMS-режим — только заглушка «скоро», структуру внутри пока не делаем.

---

## 1. База данных

Новая таблица `creator_accounts` (отдельная от `simple_users`, чтобы не смешивать с учениками):

```text
creator_accounts
  id              uuid PK
  login           text UNIQUE NOT NULL   -- имя-логин, регистр-нечувствительная уникальность
  display_name    text NOT NULL
  password_hash   text NOT NULL          -- bcrypt через pgcrypto (crypt + gen_salt)
  account_type    text NOT NULL          -- 'course_creator' | 'online_school'
  created_at, updated_at
```

- Уникальный индекс по `lower(login)` — для проверки занятости имени.
- RLS включен; политики только для `service_role` (вся работа через edge-функции). GRANT для `authenticated` и `service_role`.
- Хеш пароля — `crypt(password, gen_salt('bf'))`. Проверка — `password_hash = crypt(input, password_hash)`.

Существующие создатели в новую таблицу **не мигрируются** — для них продолжает работать общий `CREATOR_PASSWORD_HASH` как fallback.

## 2. Edge-функции

### `register-creator` (новая)

Вход: `{ login, password, accountType }`.

- Валидирует длину (логин ≥ 2, пароль ≥ 6).
- Проверяет, что `lower(login)` свободен в `creator_accounts`.
- Хеширует пароль, вставляет запись, возвращает токен сессии (как сейчас `verify-creator-password`).
- Если логин занят — 409 + сообщение «Это имя уже используется».

### `verify-creator-password` (расширить существующую)

- Сначала ищет аккаунт в `creator_accounts` по `lower(login) = lower(input)`.
  - Найден → проверяет хеш через `crypt`. При успехе возвращает `accountType` и токен.
- Если нет — fallback на текущую логику с общим `CREATOR_PASSWORD_HASH` (старые создатели). Для них `accountType = 'course_creator'`.

### `change-creator-password` (новая)

Вход: `{ currentPassword, newPassword, token }`.

- Валидирует сессионный токен, проверяет текущий пароль, обновляет хеш.
- Старым (fallback) создателям возвращает ошибку «функция доступна только после регистрации».

## 4. Новый мастер регистрации (`src/components/CreatorRegisterForm.tsx`)

Три шага в одной карточке:

1. **Выбор режима** — две большие карточки:
  - «Создатель курса» — то, что есть сейчас.
  - «Онлайн-школа» — пометка «LMS для школ и центров».
2. **Ввод данных:** логин (имя), пароль, повтор пароля.
  - Валидация: логин ≥ 2 симв., пароль ≥ 6 симв., совпадение повтора.
  - Кнопка «Зарегистрироваться» вызывает `register-creator`.
  - При ответе 409 — inline-ошибка под полем логина: «Это имя уже занято, выберите другое».
3. **Успех:** сохраняем `creator_name`, `creator_token`, `creator_account_type` в localStorage.
  - `course_creator` → редирект на `/creator`.
  - `online_school` → редирект на новый `/school` (см. ниже).

## 5. Форма входа создателя (`CreatorLoginForm.tsx`)

- При успешной проверке пароля edge-функция возвращает `accountType`. Сохраняем `creator_account_type` в localStorage.
- Редирект: `course_creator` → `/creator`, `online_school` → `/school`.
- В остальном UI не меняется.

## Открытые риски

- **Хранение пароля в открытом виде невозможно** — заменено на «Сменить пароль». Если для тебя это критично — нужно отдельно обсудить (компромисс по безопасности).
- **Учителя**: убираем кнопку с главной. Они продолжают входить, но только по сохранённой сессии или прямой ссылке. Если нужен альтернативный вход — скажи отдельно.
- **Старые создатели** видят в настройках инфо вместо кнопки смены пароля. Когда захочешь — добавим миграцию (одноразовая установка личного пароля).
