

## Problem Analysis

There are two distinct issues:

### Issue 1: Session lost on app close/reopen

In `SimpleAuthContext`, the `loadUser` function fetches the user from the database on startup. If the fetch fails for ANY reason (network error, slow connection, offline), the localStorage key is **permanently deleted**:

```js
if (data && !error) {
  setUser(data as SimpleUser);
} else {
  localStorage.removeItem(USER_STORAGE_KEY); // ← destroys session on network error!
}
```

Similarly, in `CreatorDashboard`, `validateSession` removes `creator_token`/`creator_name` from localStorage on any network error (catch block on line 180-183).

### Issue 2: "Keeps logging out after re-login" (after the update)

The `firebase-messaging-sw.js` now has `skipWaiting()` + `clients.claim()`. This Firebase SW is registered at scope `/`, which **conflicts with the PWA SW** (also at scope `/`). When the Firebase SW activates and calls `clients.claim()`, it can trigger the PWA's `controllerchange` handler, causing a page reload loop. Each reload re-runs `loadUser`, which can fail if the network isn't ready yet, deleting the session.

## Solution

### 1. `SimpleAuthContext.tsx` — Don't delete session on network errors

Only remove `USER_STORAGE_KEY` if the user genuinely doesn't exist (404-like), not on network/transient errors:

```js
if (storedUserId) {
  try {
    const { data, error } = await supabase
      .from("simple_users")
      .select("*")
      .eq("id", storedUserId)
      .single();

    if (data && !error) {
      setUser(data as SimpleUser);
    } else if (error && error.code === 'PGRST116') {
      // Row not found — user was deleted, clear session
      localStorage.removeItem(USER_STORAGE_KEY);
    }
    // On other errors (network, timeout), keep localStorage intact
    // and leave user as null — the app will show loading or retry
  } catch {
    // Network failure — don't remove session
    console.warn("Failed to load user, keeping session for retry");
  }
}
```

### 2. `CreatorDashboard.tsx` — Don't delete creator session on network errors

In `validateSession`, the catch block currently removes `creator_token` and `creator_name`. Change it to keep them and show the dashboard with cached `creatorName`:

```js
} catch (err) {
  console.error('Session validation error:', err);
  // Network error — don't remove session, use cached name
  setCreatorName(name);
  setIsLoading(false);
}
```

### 3. `firebase-messaging-sw.js` — Remove `skipWaiting`/`clients.claim`

These conflict with the PWA SW at the same scope. Remove lines 6-9. The Firebase SW doesn't need to claim clients — it only needs to handle push events. The PWA SW (generated by vite-plugin-pwa) already has its own `skipWaiting`/`clientsClaim` config:

```js
// Remove these lines:
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', (event) => {
  event.waitUntil(self.clients.claim());
});
```

### 4. `firebase.ts` — Remove `registration.update()` call

The forced update call can trigger SW replacement loops. Remove the `registration.update()` line (keep `updateViaCache: 'none'`).

## Summary of changes

| File | Change |
|------|--------|
| `SimpleAuthContext.tsx` | Only remove localStorage on "row not found", not on network errors |
| `CreatorDashboard.tsx` | Don't clear creator session on network errors in catch block |
| `firebase-messaging-sw.js` | Remove `skipWaiting`/`clients.claim` to prevent PWA SW conflicts |
| `firebase.ts` | Remove `registration.update()` to prevent SW update loops |
