## Проблема

1. В разделе «Материалы» у **автора** (`CreatorMaterialsTab`) после редизайна видна только кнопка «Управление материалами», а сам список уже добавленных материалов не показывается до тех пор, пока не открыть «Редактировать». Нужно показывать список существующих материалов сразу под кнопкой.
2. Нет поиска по материалам. Нужно добавить поиск (по названию папки, файла, текста, ссылки) сверху списка существующих материалов — у автора, ученика и учителя.

## Что меняем

### 1. Автор: показать существующие материалы сразу

Файл: `src/components/creator/CreatorMaterialsTab.tsx`

- Под блоком с `ProductSwitcher` + кнопкой «Управление материалами» добавить read-only список материалов выбранного продукта.
- Использовать существующий хук `useProductMaterials(productId, { creatorOnly: true })`.
- Поведение списка:
  - Корневой уровень показывает папки и файлы/ссылки/тексты без `parent_id`.
  - Папки кликабельны — раскрываются/сворачиваются inline (как у ученика в `MaterialsTab`), показывая вложенные файлы.
  - Для файлов/ссылок/текста — иконка типа + название + (опционально) короткая подпись типа. Никаких кнопок скачать/редактировать здесь нет — управление по-прежнему только через кнопку «Управление материалами» → «Редактировать».
  - Loading state: спиннер; пустой state: короткий текст «Пока нет материалов» / «Әзірге материалдар жоқ».

### 2. Поиск над списком материалов (автор, ученик, учитель)

Общий компонент: `src/components/materials/MaterialsSearchBar.tsx` (новый)

- Контролируемый `Input` с иконкой `Search`, placeholder «Поиск по названию…» / «Атау бойынша іздеу…».
- Кнопка-крестик для очистки.

Логика фильтрации (одинаковая везде):

- Сравнение `material.title.toLowerCase().includes(query.toLowerCase().trim())`.
- Если запрос пустой — обычное иерархическое отображение (папки + содержимое).
- Если запрос непустой — плоский список: показываем все материалы (любого уровня вложенности), у которых `title` совпадает. Папка, чей `title` совпадает, тоже показывается как карточка (без авто-раскрытия детей). Это покрывает «название группы (папки), файла, текста, ссылки».
- Подсчёт результатов под полем поиска: «Найдено: N» / «Табылды: N».

Интеграция:

- `CreatorMaterialsTab.tsx` — поиск над новым списком (см. п.1). Состояние `query` локальное.
- `src/components/dashboard/MaterialsTab.tsx` (ученик) — поиск над `groupCreatorMaterials` / `groupTeacherMaterials`. Фильтр применяется к плоскому массиву `materials` до группировки. При активном поиске не группируем по продукту, а показываем плоский список карточек (со всеми текущими действиями: download / view / play / open). Locked-материалы остаются locked.
- `src/components/teacher/TeacherMaterialsTab.tsx` — поиск над списком «Мои материалы». Поскольку каждый продукт сейчас в отдельной карточке с `TeacherMaterialsManager`, поиск ставим **внутри** `TeacherMaterialsManager` (см. ниже).
- `src/components/teacher/TeacherMaterialsManager.tsx` — поиск над текущим списком материалов учителя (отображение в режиме «список существующих», не в форме добавления/редактирования). Та же логика фильтрации.
- `src/components/creator/ProductMaterialsManager.tsx` — поиск в режиме `mode="edit"` над списком материалов внутри диалога редактирования (там, где есть кнопки Edit/Delete). В режиме `mode="add"` поиск не нужен.

### 3. Возможная причина «не видно сразу» помимо UI

Помимо того, что список просто не отрисовывался у автора, проверим что `useProductMaterials` с `creatorOnly: true` отрабатывает корректно при первом рендере (запрос включён `enabled: !!productId`, `selectedId` ставится в `useEffect` после загрузки `products` — это уже сделано). Дополнительных правок к загрузке/RLS не делаем.

## Что НЕ трогаем

- Схема БД, RLS, edge-функции, `useMaterials`/`useTeacherMaterials` хуки.
- Логика загрузки файлов, токены, office-просмотр.
- Логика прав скачивания (только ученики могут скачивать материалы автора — без изменений).
- Формы добавления/редактирования (только добавляем поиск над списком в edit-режиме).
