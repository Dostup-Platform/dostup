## Что меняем

На главной странице входа (`src/pages/Index.tsx`) кнопка «Войти» сейчас при незнакомом имени автоматически создаёт нового студента. Это нужно убрать.

После изменения:

- Если введённая пара логин+пароль соответствует существующему создателю курса → вход как создатель (как сейчас).
- Если такая пара соответствует существующему студенту/учителю (где «логин» — имя, «пароль» — фамилия, т.е. полное имя есть в `simple_users`) → вход в их кабинет.
- Если ни то ни другое → показать ошибку «Логин или пароль неверный». Никакой новый пользователь не создаётся.

Новые студенты по-прежнему попадают в систему только через ссылку-приглашение от создателя/школы — этот поток уже существует и не меняется.

## Технические детали

Файл: `src/pages/Index.tsx`, функция `handleRegister`.

1. После неуспешной проверки `verify-creator-password` вместо `loginOrRegister(fullName)` использовать существующий `loginByName(fullName)` из `SimpleAuthContext` (он возвращает ошибку, если имя не найдено, и ничего не создаёт).
2. Убрать ветку `isNewUser` / `setShowRoleSelection(true)` — она больше недостижима из формы входа.
3. При ошибке от `loginByName` показывать `toast.error(t("invalidCredentials"))`.
4. Из деструктуризации `useSimpleAuth()` убрать `loginOrRegister`, добавить `loginByName`.

Регистрация создателей продолжает работать через отдельную кнопку «Регистрация» (`CreatorRegisterForm`) — её не трогаем. Поток приглашения студентов через `signup_tokens` / `verify-signup-token` тоже остаётся без изменений.
