## Цель

В разделах **Материалы**, **Объявления** и **Расписание** автора убрать промежуточный шаг «выбор продукта списком». Вместо этого:

1. Если **нет продуктов** — показать заглушку с предложением сначала создать продукт.
2. Если **один продукт** — он выбран по умолчанию, переключатель не показывается.
3. Если **2+ продукта** — слева сверху отображается кнопка-селектор с названием текущего продукта, по клику открывается список.
4. Контент раздела сразу показывает рабочий интерфейс выбранного продукта (как сейчас работает «Расписание» после выбора продукта — формы создания расписания/слотов).

## Изменения

### 1. Общий компонент `ProductSwitcher`
Новый файл `src/components/creator/ProductSwitcher.tsx`:
- Принимает `products`, `selectedId`, `onChange`.
- Если 1 продукт — рендерит просто текстовый бейдж с названием (без выпадашки).
- Если 2+ — кнопка слева сверху с названием продукта и иконкой ▾, открывает `DropdownMenu` со списком всех продуктов.

### 2. Общий компонент `NoProductsEmptyState`
Новый файл `src/components/creator/NoProductsEmptyState.tsx`:
- Иконка + текст: «Сначала создайте продукт в разделе "Продукты", чтобы добавлять сюда материалы / объявления / расписание».
- Кнопка «Перейти в Продукты» (вызывает проп `onGoToProducts`, который переключит вкладку через уже существующий механизм навигации в `CreatorDashboard`).

### 3. `CreatorMaterialsTab.tsx` — переписать
- Удалить экран «список продуктов → клик → менеджер».
- Логика выбора продукта:
  - `products.length === 0` → `NoProductsEmptyState`.
  - `products.length >= 1` → стейт `selectedProductId` (по умолчанию первый продукт), сверху `ProductSwitcher`, ниже сразу рендерится `ProductMaterialsManager` для выбранного продукта.
- `ProductMaterialsManager` уже умеет показывать UI создания материалов — он будет видим сразу.

### 4. `CreatorAnnouncementsTab.tsx` — переписать
- Аналогично: убрать список продуктов.
- `NoProductsEmptyState` / `ProductSwitcher` / прямой рендер `ProductAnnouncementsManager` (убрать у него кнопку «К продуктам» — заменить на `ProductSwitcher` сверху).
- Форма «Создать пост» и поле «Ссылка на чат/группу» уже отображаются в менеджере — будут видны сразу.

### 5. `CreatorScheduleTab.tsx` — адаптировать
- Текущий раздел уже даёт сразу видеть кнопки «Создать расписание» и «Создать слоты» — оставить.
- Добавить сверху `ProductSwitcher` (или заглушку, если нет продуктов).
- Ввести стейт `selectedProductId`. Все запросы schedules/slots фильтровать по `selectedProductId` вместо всех `productIds`.
- В форме создания расписания убрать выбор продукта (`scheduleForm.productId`) — использовать `selectedProductId` автоматически.
- Если нет продуктов → `NoProductsEmptyState` (вместо текущего поведения).

### 6. Навигация «Перейти в Продукты»
- В `CreatorDashboard.tsx` уже есть управление активным табом — пробросить функцию `setActiveTab('products')` в каждую из трёх вкладок, чтобы кнопка из `NoProductsEmptyState` работала.

## Технические детали

- Никаких изменений БД/edge functions не требуется — только UI.
- `ProductMaterialsManager` и `ProductAnnouncementsManager` принимают `onBack` / `onClose` — в новых обёртках эти пропы можно передавать как no-op или удалить кнопку возврата внутри менеджеров (заменим на `ProductSwitcher`, который и есть способ «сменить продукт»).
- Сохранение текущего выбранного продукта между переключениями вкладок — не обязательно (локальный `useState` в каждой вкладке достаточно; по умолчанию берётся `products[0]`).
- Локализация (ru/kk) для новых текстов через `useLanguage()`, в стиле существующих ключей.
