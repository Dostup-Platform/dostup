## Что меняем

### 1. Главная страница (`src/pages/Index.tsx`) — единая форма входа

Два текущих поля «Имя» и «Фамилия» переименовываем в **«Логин»** и **«Пароль»** (тип поля у пароля — `password` с иконкой глаза). Кнопка submit остаётся **«Войти»**.

Один вход обслуживает всех:
- **Старые создатели**: логин = имя создателя, пароль = существующий общий `CREATOR_PASSWORD_HASH` (или личный, если уже сменили). Уже реализованный `verify-creator-password` это умеет.
- **Новые создатели**: логин = их `login` из `creator_accounts`, пароль = их личный пароль.
- **Учителя**: логин = имя, пароль = фамилия (как сейчас работает teacher-login по имени+фамилии).
- **Ученики**: логин = имя, пароль = фамилия (старый flow `loginOrRegister(fullName)` использует пару).

Нижний блок: убираем кнопку **«Войти»** полностью. Оставляем только одну кнопку **«Зарегистрироваться»** (для создателей школ/курсов). Иконку и стиль сохраняем.

### 2. Логика проверки (`src/contexts/SimpleAuthContext` + edge functions)

Новый метод `loginUnified(login, password)`:
1. Сначала вызываем `verify-creator-password` (имя+пароль). Если успех → сохраняем `creator_*` в localStorage и редирект на `/creator` или `/school` по `accountType`.
2. Иначе ищем `teacher` в `simple_users` по `name=login AND last_name=password AND role='teacher'`. Если найдено → teacher flow.
3. Иначе делегируем существующему `loginOrRegister(\`${login} ${password}\`)` для студентов (вход или регистрация нового студента). Замечание: новый студент создаётся как и раньше — поле «Логин» это его имя, «Пароль» это фамилия.

Никаких изменений в БД — переиспользуем существующие данные. Лейблы меняются только в UI.

### 3. Форма регистрации создателя (`src/components/CreatorRegisterForm.tsx`) — фикс шапки

Сейчас кнопка «Назад» поставлена `absolute left-4 top-4` поверх `CardTitle`, и на узких экранах перекрывает заголовок. Перестраиваем шапку:

- Убираем `absolute` у кнопки.
- `CardHeader` становится grid из 3 колонок: `[back] [title] [spacer]`, где боковые колонки одинаковой ширины, а заголовок центрирован и не пересекается с кнопкой.
- На мобильном (узких экранах) кнопка «Назад» показывает только иконку `ArrowLeft` без слова «Назад» (aria-label остаётся), на `sm:` и выше — иконка + текст.
- Заголовок получает `truncate` и адекватный `text-xl sm:text-2xl` чтобы не вылезал.

Тот же приём применяем в `CreatorLoginForm.tsx` если там такой же absolute back-button (проверю при реализации и поправлю одинаково для консистентности).

### 4. Переводы (`src/lib/translations.ts`)

Добавляем/используем ключи:
- `loginField` — «Логин»
- `passwordField` — «Пароль»
- `loginPlaceholder` — «Введите логин»
- `passwordPlaceholder` — «Введите пароль»
- `invalidCredentials` — «Неверный логин или пароль»

Для RU и KK.

## Что НЕ трогаем
- Структуру БД, edge-функции `register-creator` и `change-creator-password`.
- Поток для нового создателя (выбор типа аккаунта → логин/пароль) остаётся как есть.
- Дашборды `/creator` и `/school`.

## Открытые риски
- Новые ученики теперь регистрируются той же кнопкой «Войти» (если такого логин+пароль нет в системе — создаётся новый студент). Если хотите, чтобы регистрация ученика была явной — скажите, добавлю отдельную кнопку «Я ученик».
- Если у учителя имя совпадает с именем создателя — приоритет получит создатель (попытка №1). Можно поменять порядок, скажите.
