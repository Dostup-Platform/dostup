# Сложная материалы

## Изменения

- Варианты идут в порядке «Файл / Ссылка / Текст / Папка». У каждого свой черновик; переключение сохраняет введённое, кнопка «Добавить» сохраняет все заполненные варианты в конец текущей папки/корня. Уже сохранённые элементы исключаются из черновика, чтобы повтор после частичной ошибки не дублировал их. Создаваемая папка содержит только название.
- Выбор файла заполняет его название, но не показывает сообщение об успешном добавлении. Выбранные файлы расположены под полем добавления; успех показывается после сохранения кнопкой «Добавить». Надпись «Выберите файл(ы)» убрана; пустой выбор показывает «Вставьте файл». Подсказки загрузки адаптированы для компьютера и телефона.
- Светло-оранжевая кнопка с шестерёнкой «Настроить добавление» задаёт скачивание и расписание новым выбранным файлам. Скачивание по умолчанию включено, выбор сохраняется в этом браузере между открытиями формы. Расписание при новом открытии выключено. У каждого файла параметры можно изменить независимо.
- У файлов и ссылок «Запланировать добавление» открывает календарь с выбором даты и времени через отдельную кнопку. Даты редактируются в локальном времени пользователя; поля под переключателем нет. Для текста и папки расписания нет.
- Убрана настройка новой обложки. Существующие обложки сохраняются; изменение названия или прав не очищает их.
- Крестик файла расположен справа от поля названия, становится белым на оранжевом фоне и показывает «Убрать файл?». Крестик окна показывает слева «Изменения не сохранятся» и сразу закрывает форму, сбрасывая черновики. Клик снаружи и Escape окно не закрывают.
- Тексты открываются отдельным диалогом без крестика, кнопка разворачивания строки удалена. В карточке текста есть копирование. «Дом» заменён на «Главная»; в корне это простой текст без наведения, внутри папки — кнопка возврата.
- Список выбора показывает два файла: на компьютере в две колонки слева направо, на телефоне друг под другом. Дополнительные файлы прокручиваются внутри списка, заголовок и кнопка добавления остаются на месте.
- На телефоне карандаши выровнены в постоянную колонку, меню четырёх разделов имеет строки 48 px / текст 16 px. Четыре типа добавления помещаются в одну строку при 320 и 390 px. На компьютере название продукта занимает свободную ширину до разделов материалов.

## Загрузка и размеры

Сохранён текущий маршрут новых загрузок в S3. Выбор единственного хранилища и перенос старых данных не входят в задачу.

При браузерном сетевом/CORS-сбое файл до 20 MiB повторно передаётся через авторизованный серверный обработчик в тот же S3-объект. Повтор использует прежний путь, проверяет разрешённый продукт/папку преподавателя и bucket. Ошибки доступа/отмены не повторяются автоматически. Большие файлы продолжают загружаться напрямую; для них необходим исправный CORS S3. Тело серверного повтора ограничено, чтобы не превышать память Edge Function.

Ошибки настройки сервера показываются отдельно от ошибок интернета. MIME-тип передаётся согласованно. Исправлены совместимость типов AWS SDK и именованный экспорт MD5, используемый существующей функцией настройки CORS.

Новые файлы сохраняют фактический file.size. После создания/изменения/удаления/восстановления обновляется запрос хранилища. Для старых объектов Supabase Storage сначала читаются метаданные, затем применяется совместимый Range-запрос; для S3 используется Range. В ответе 206 берётся общий размер из Content-Range, а не размер однобайтового фрагмента. Потоки закрываются, неудачные обновления не считаются успешными.

Ссылки и пустые папки показывают 0 B, размеры вложенных папок суммируются. Неопределённый размер файла не подменяется нулём; при недоступности метаданных отображается «Размер недоступен».

## Первоначальное состояние общей тестовой базы

Проверка через предоставленный тестовый seller на wkqyimqbpmzhscuwhode.supabase.co показала:
- вход и чтение тестовых материалов работают;
- s3-presign-upload возвращает HTTP 500 с Server misconfiguration до отправки файла.

В текущем обработчике этот ответ означает отсутствие одного или нескольких серверных параметров:
- AWS_ACCESS_KEY_ID;
- AWS_SECRET_ACCESS_KEY;
- AWS_S3_BUCKET;
- AWS_S3_REGION.

Эти параметры задаются в секретах Supabase Edge Functions, не во frontend .env и не в клиентских переменных Vercel. Значения ключей в репозиторий не добавлять.

Для проверки загрузки:
1. Проверить серверные настройки S3 и права доступа выбранного bucket.
2. Опубликовать s3-presign-upload, upload-material, material-file-sizes с обновлёнными shared-модулями. Для применения исправления существующего CORS helper также опубликовать upload-product-media. Обновить manage-materials, чтобы создание материала не отправляло удалённое из формы поле cover_url, отсутствующее в схеме общей тестовой базы.
3. В CORS bucket разрешить PUT для используемых адресов приложения/превью, заголовок Content-Type; для браузерного чтения — GET/HEAD и необходимые заголовки ответа. Не менять CORS в обработчике обычной загрузки.
4. Проверить загрузку малого файла, несколько файлов, файл свыше 20 MiB и обновление размеров. Убедиться в совпадении размера сохранённого объекта.
5. Проверить материалы с покупательского аккаунта и независимые даты доступа файлов.

Миграции базы для этой задачи не требуются. При первоначальной разработке функции и настройки общей/рабочей среды не изменялись; реальная передача файла была заблокирована указанной конфигурацией. Последующее развёртывание и проверка общей тестовой среды описаны ниже.

## Проверка общей тестовой среды 7 ноября 2026

Проект: Dostup-Preview (`wkqyimqbpmzhscuwhode`), отдельный бакет `dostup-materials-preview` в `eu-north-1`.

Все четыре параметра AWS добавлены владельцем. В тестовом проекте опубликованы пять обработчиков: s3-presign-upload, upload-material, material-file-sizes, upload-product-media и manage-materials. Исходники опубликованных модулей скачаны и сверены с подготовленными сборками. Текущие настройки проверки JWT сохранены; неавторизованные запросы на загрузку отклоняются.

В manage-materials удалена передача несуществующего столбца cover_url при создании. Новая колонка и миграция для этого не нужны. При публикации сохранена уже действующая в проекте версия проверки доступа: для оплаты по периодам достаточно любого ещё открытого оплаченного периода.

Проверено настоящими запросами с предоставленным тестовым seller:
- прямой PUT служебного файла 71 B — HTTP 200;
- повтор того же файла через авторизованный multipart-обработчик — HTTP 200, путь объекта сохраняется;
- создание материала с размером 71 B и повторное определение размера после очистки этого поля — 71 B, один объект обновлён, неопределённых размеров нет;
- скачивание по одноразовому токену — HTTP 200, содержимое совпадает;
- временная запись материала удалена после проверки;
- прямая передача 21 MiB — HTTP 200; Range-запрос вернул HTTP 206 и полный размер 22020096 B. Служебный объект после проверки снова содержит 71 B;
- вызов multipart-повтора с 21 MiB был прерван по тайм-ауту; HTTP 413 в этой среде не подтверждён. Клиент не использует повтор для файлов больше 20 MiB; соответствующее ограничение и выбор маршрута покрыты тестами;
- сборка приложения, Deno check всех пяти обработчиков и 13 тестов материалов проходят.

После предоставления прав владельцем и согласования замены конфигурации в бакете dostup-materials-preview сохранено правило из [materials-preview-cors.json](./materials-preview-cors.json). Оно разрешает GET/PUT/HEAD только перечисленным адресам localhost и превью PR. Настройки публичного доступа и bucket policy не менялись.

Preflight PUT с localhost:8080 и адреса превью PR теперь возвращает HTTP 200 с соответствующим Access-Control-Allow-Origin. В настоящем браузере через форму приложения на localhost:8085 одновременно выбраны и сохранены два файла: 63 B и 21 MiB (22020096 B). Оба появились в библиотеке с правильными размерами в сохранённых записях. Файл 21 MiB загрузился напрямую в S3: клиент не использует серверный повтор для файлов больше 20 MiB.

Две временные записи материалов удалены после проверки. Диагностические файлы и скриншоты не входят в репозиторий. Блокер CORS в общей тестовой среде устранён; для новых адресов превью потребуется добавить их origin в правило.
