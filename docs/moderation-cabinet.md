# Кабинет модератора и жалобы

Ветка: `кабинет-модератора`. Изменения подготовлены локально; рабочая база и опубликованный сайт не изменялись. Удаление отзывов и запросы на их удаление в эту задачу не входят.

## Поведение

- Жалоба на продукт или витрину продавца доступна после входа. Отправитель определяется по серверной сессии. Причины: несоответствие описанию, неприемлемый контент, выдача себя за другого человека, другое. Комментарий всегда открыт; обязателен только для «Другое», максимум 4000 символов.
- Новая жалоба в одной транзакции ограничивает профиль продавца, сохраняет прежние настройки всех его продуктов и делает продукты приватными и приостановленными. Создание, публикация, продажи, выдача новых покупок, подписок и пробного доступа запрещены на уровне базы. Существующие продукты можно редактировать и удалять. Полученный ранее доступ покупателей сохраняется.
- Жёлтыми становятся карточки продуктов, на которые поступили открытые жалобы; при жалобе на профиль — все карточки продавца. Остальные продукты тоже нельзя продавать до проверки.
- Ограничения и действия модератора приходят в уведомления кабинета и в личный чат с техподдержкой. Статусы продавца и модератора обновляются каждые 15 секунд.
- «Поступившие» включает новые жалобы и жалобы с запросом исправления. Счётчик не зависит от просмотра раздела. «Все» сохраняет решения и порядковые номера повторных жалоб на продавца и продукт. Удаление продукта сохраняет его название и историю жалоб.
- Модератор может написать заявителю через его чат техподдержки, посмотреть все продукты автора, открыть страницу продукта в оформлении маркетплейса, материалы и папки, сообщения продукта, расписание и последние 500 личных сообщений автора с вложениями. Предпросмотр проверяет сессию модератора и не выдаёт сессию продавца или доступ покупателя. Ссылки на приватные файлы подписываются на ограниченное время.
- «Запросить исправление (72 часа)» требует описание изменений. Срок хранится на сервере и отображается у обеих сторон. Повторным нажатием таймер не продлевается. За 24 часа до конца продавцу приходит напоминание; после истечения срока модератору приходит уведомление. Автоматической блокировки по таймеру нет.
- Отклонение последней открытой жалобы восстанавливает прежние настройки видимости и паузы. При других открытых жалобах ограничения сохраняются.
- Блокировка распространяется на связанные профили продавца и покупателя, отзывает сессии приложения и Supabase Auth, блокирует вход, создание новых профилей и покупки. Сохраняются почта, Auth ID, Google subject и доступные сигналы браузера/IP. Открытые жалобы связанных продавцов переходят в заблокированные. Старая кнопка разблокировки одного профиля не снимает блокировку по жалобе.

## Развёртывание

1. Применить `supabase/migrations/20261109144210_fraud_moderation.sql` через штатный процесс миграций проекта. Миграция поддерживает установки, где таблица жалоб раньше была создана вне миграций. Приватную схему `moderation` не добавлять к схемам Data API.
2. Убедиться, что включён `pg_cron`. Миграция создаёт задачу `moderation-deadlines`, если расширение установлено или предзагружено. На PostgreSQL без предзагрузки выводится NOTICE: расписание требуется включить до выпуска функционала. Проверка и установка задачи:

```sql
select jobname, schedule, command, active
from cron.job where jobname = 'moderation-deadlines';

select cron.schedule(
  'moderation-deadlines',
  '*/5 * * * *',
  'SELECT public.process_moderation_deadlines()'
);
```

Уведомления сохраняются независимо от открытого браузера. Допустимая задержка — до пяти минут. Это уведомления в приложении и в чате техподдержки; почта не используется.

3. Развернуть Edge Functions. Изменения общих модулей `session`, `s3` и `tokenized-download` затрагивают несколько обработчиков, поэтому развернуть все локальные функции штатной командой `supabase functions deploy`, затем фронтенд. Не использовать `--prune`.
4. Проверить совместно новый фронтенд и Edge Functions: обращения в поддержку теперь требуют сессию, поэтому старый клиент не должен оставаться единственной опубликованной версией. Обновлённые файловые клиенты передают сессию.
5. Для блокировки по IP задать Edge secret `MODERATION_TRUSTED_IP_HEADER` только с заголовком, который доверенный шлюз гарантированно перезаписывает. По умолчанию IP не доверяется. Клиентское поле `ip` игнорируется. Для серверных обращений сохраняется SHA-256 от IP и браузерного идентификатора, исходные значения не пишутся в таблицы модерации.
6. Перед публикацией выполнить Security Advisors на целевом проекте и проверить сценарий с тестовым продавцом. Новые таблицы закрыты RLS и отзывом прав `anon`/`authenticated`; RPC решений доступны только `service_role`; привилегированные функции находятся в приватной схеме с фиксированным `search_path`.

`Device ID` в браузере — случайный идентификатор установки в localStorage, не аппаратный номер устройства. Очистка данных браузера, другой браузер, VPN или смена сети могут обойти устройство/IP. Основные постоянные блокировки опираются на серверные идентификаторы почты, Auth и Google. Гарантировать запрет регистрации с полностью другой идентичностью веб-приложение не может.

## Проверки

- Миграция выполнена с нуля в отдельной локальной базе PostgreSQL 17.11. `supabase/tests/moderation.sql`: 42 проверки ограничений, восстановления настроек, истории, таймеров, однократных уведомлений, блокировки идентичности и прав доступа. Тест завершается ROLLBACK. `moderation_fixture.sql` — минимальная схема только для пустой тестовой базы, не для рабочей базы.
- `deno test --allow-env supabase/functions/_shared/moderation.test.ts`: 12 тестов, включая подмену отправителя, доверие к IP, историю свыше 1000 жалоб, повторные жалобы и обход старого доступа к файлам через поле role.
- `deno check` изменённых Edge Functions проходит. Supabase Security Advisors в локальной тестовой базе: замечаний не найдено.
- Chromium с подставным API: форма жалобы, предпросмотр реального компонента страницы продукта, материалы, запрос исправления, таймер, счётчики, отклонение и история, открытие чата заявителя, мобильный экран 390 px без горизонтального переполнения.
- `npm run build` проходит. Полный `tsc` содержит те же 7 ошибок, что и исходный HEAD: `CreatorUsersTab`, `ScheduleTab`, `SlotCreationWizard`; результат сравнен с чистой копией исходной ветки.
